## 1. 信号回测方法论

### 时间基准 (P-FIX)

| 参数 | 定义 | 来源 |
|------|------|------|
| entry_price | 首次信号时间的 gecko_market_data 最近价 | meta_snapshots MIN(scan_time) WHERE verdict='ACC' |
| ret_Xd | `(price_Xd - entry) / entry * 100` | gecko_market_data scan_time >= signal_date + Xd |
| MDD | `(min_price_since_signal - entry) / entry * 100` | 信号日至今所有价格的最低点 |

### 关键约束

- **过滤当天信号**: 信号日=今天的代币不纳入回测（持有 <1d 无意义）
- **MDD 从信号日起算**（非从最高点），符合实际持仓视角
- **DB 存储格式**: 百分比值直接存储（10% 存为 10.0），报告用 `f"{ret:+.1f}%"` 显示

### 实测基线 (2026-05-06)

| 信号级别 | 样本 | 至今胜率 | 至今均收 | 至今中位 | MDD中位 |

| DIAMOND | 7 | 86% | +3.2% | +4.2% | -4.2% |
| RED | 14 | 43% | +32.6% | -3.7% | -15.8% |
| YELLOW | 92 | 52% | +5.3% | +0.3% | -6.0% |

## 2. Holder 迁移方法论

### 留存率计算

```
retention_7d = len(old_set ∩ new_set) / len(old_set) × 100
```
- old_set: 7天前 bubblemap Top50 holder 地址集合
- new_set: 最新 bubblemap Top50 holder 地址集合

### 评级体系

| 留存率 | 评级 | 含义 |
|--------|------|------|
| ≥ 90% | 🔒极稳 | 长期持有者为主 |
| 75-89% | ✅稳定 | 正常换手 |
| 60-74% | ⚠波动 | 加速换手 |
| < 60% | ❌流失 | 大规模换手 |

### 遗漏检测规则 (复合条件)

```
IF retention_7d < 50%
   AND top10_delta_7d < 0   (Top10 持仓占比在减少)
   AND meta_verdict ≠ DIST
THEN → 标记 "应为 DIST"
```

### ⚠ 已知局限: 低留存 ≠ 出货

**SKYAI 案例 (2026-05-06)**:
- 留存率 17%、Top10Δ -5.7% → 遗漏检测标记 "应为 DIST"
- 实际至今收益 **+220.2%** → 信号完全有效

**根因**: 庄家拉盘 + 散户追涨换手。Top50 地址大换血但**价格暴涨**。

**方法论结论**: 留存率反映的是**地址换手**而非**筹码流向**。需同时看:
1. Top10 占比绝对值（≥50% = 庄控仍在）
2. 价格趋势（涨 = 可能是庄家拉盘换手）
3. 新进地址数 vs 退出地址数（净流入 = 吸筹特征）

### 底部吸筹识别

```
IF retention_7d < 50%
   AND top10_delta_7d > 0   (Top10 占比在增加)
THEN → "散户换手，大户加仓" → 底部吸筹信号
```

**实测案例**: DAM (+15.3% Top10Δ)、TAC (+25.2% Top10Δ)

## 3. 积分时序方法论

### 斜率计算

```python
slope = numpy.polyfit(x=[0,1,2,...,N-1], y=score_history, deg=1)[0]
```
- N = meta_snapshots 历史轮次数（每 12h 一轮）
- 正斜率 = 信号增强，负斜率 = 信号衰减

### 平序列归零

```
IF σ(score_history) < 0.05:
    slope = 0  # 分数完全不变，斜率无意义
```

### 高波动阈值

| σ | 含义 |
|---|------|
| < 0.5 | 稳定 |
| 0.5-1.0 | 波动 |
| > 1.0 | 高波动（需关注信号可靠性） |

### 跃变检测

```
IF |delta_score| >= 1.5 BETWEEN 相邻两轮:
    → 标注 "⚡跃变" + 原因分析
```

## 4. 流动性健康度方法论

### 量变化计算

```
vol_change = (volume_24h - avg_7d_volume) / avg_7d_volume × 100
```

### 量价背离定义

| 类型 | 条件 | 含义 |
|------|------|------|
| 价涨量缩 | price_24h_change > 5% AND vol_change < -30% | 拉盘无力 |
| 价跌量增 | price_24h_change < -5% AND vol_change > 30% | 恐慌抛售 |

### 流动性枯竭告警

```
IF volume_24h < avg_7d × 30%   → 交易几乎停滞
OR reserve_usd < $10,000       → LP 枯竭
```

### ⚠ 已知局限: volume_24h=0

129 个 token_history 中约 60 个 `volume_24h=0`，原因:
- gecko 未采集该代币数据
- 代币已退市/迁移链
- 非 DEX 代币无链上交易数据

**处理**: 流动性模块自动跳过 volume=0 代币，不影响其他模块评估。

## 5. 信号质量评估方法论

### Precision / Recall / F1

| 指标 | 公式 | 2026-05-06 实测 |
|------|------|----------------|
| Precision | ACC且盈利 / 所有ACC | 64% (23/36) |
| Recall | ACC且盈利 / 所有盈利 | 38% (23/60) |
| F1 | 2×P×R / (P+R) | 48% |

### 引擎组合胜率矩阵 (2026-05-06)

| 引擎组合 | 样本 | 至今胜率 | 至今中位收益 | MDD中位 |
|----------|------|---------|-------------|---------|
| M+U | 3 | 100% | +4.2% | -4.2% |
| M+O+W | 16 | 69% | +3.1% | -5.7% |
| M+W | 15 | 60% | +1.0% | -6.1% |
| M+O | 34 | 53% | +0.6% | -6.0% |
| M | 29 | 45% | +0.0% | -4.3% |

### 关键发现

| 发现 | 数据 | 含义 |
|------|------|------|
| unified 引擎最准但样本小 | 71% precision, N=7 | 需积累更多样本 |
| whale 引擎拖低组合 | O+W 0%(N=3) vs M+O 53% | whale_score 权重需评估 |
| 高积分≠高胜率 | ≥7分 33% vs 3-5分 69% | 可能过拟合 |
| 3引擎最佳 | 67% 胜率 vs 4引擎14% | 4引擎过滤太严 |
| Recall 偏低 | 38% → 漏网 62% | 覆盖面不足 |

### 漏网之鱼特征

| 代币 | 收益 | 信号级别 | 综合分 | 遗漏原因 |
|------|------|---------|--------|---------|
| TAC | +340.7% | YELLOW | 1.0 | 引擎未覆盖 |
| SPACE | +243.0% | RED | 2.0 | 积分未达阈值 |
| UB | +103.4% | RED | -0.5 | 积分未达阈值 |

**方法论反思**: YELLOW 信号（单引擎命中）中隐藏高收益代币。当前 ACC 阈值（≥3分）可能过高，Recall 提升需降阈值或扩展引擎覆盖。

## 7. 待验证假设 (Tracking)

> 以下假设需在 2026-05-10 前后用最新数据验证

### H1: 低留存+高收益代币的后续走势

- **假设**: SKYAI 类代币（留存17%但涨220%）最终会回落
- **跟踪**: 记录 SKYAI 0506→0510 价格走势
- **判定**: 若回落 >30% → 遗漏检测有效，应加入仲裁; 若继续涨 → 低留存是换手特征非出货

### H2: 3引擎组合稳定优于4引擎

- **假设**: M+O+W(69%) 持续优于 ≥4引擎(14%)
- **跟踪**: 0510 数据中 M+O+W 胜率是否仍 >60%
- **判定**: 若稳定 → 4引擎组合可能过滤过严

### H3: 积分3-5区间是最优信号带

- **假设**: 3-5分区间(69%胜率) 持续优于 ≥7分(33%)
- **跟踪**: 0510 数据分桶胜率
- **判定**: 若稳定 → ACC 阈值可维持在3; 高分可能是过拟合

### H4: Recall 提升路径

- **假设**: 降低 ACC 阈值从3→2 可以捕获 TAC/SPACE 类漏网代币
- **跟踪**: 回测2分代币中有多少盈利
- **判定**: 若2分胜率 >45% → 值得降阈值
